# R_006 (`192.168.20.56`) ROS2 구조와 EasyLoop 연결

조사일: 2026-09-29. 로봇은 SSH로 **조회만** 했다. 06:48 UTC 조사에서는 `bringup`이 실행 중이었고, 08:49 UTC 재조회에서는 해당 프로세스가 종료되어 있었다. 아래 실행 상태는 06:48 UTC 스냅샷, 파일·서비스 경로는 로봇의 코드와 설정을 바탕으로 한다. 프로세스 존재와 lifecycle `active`는 주행·충전의 물리적 준비 상태를 보증하지 않는다.

## 터미널 명령

대화형 Bash는 `~/.bashrc:108-109`에서 `~/.bash_aliases`를 읽는다. 실제 `bringup`은 `~/.bash_aliases:1-73`의 함수다. `~/.bashrc:164`가 읽는 `~/.bringup_normal.sh`는 별개의 `bringup_normal()`을 정의한다.

`bringup()`은 네 파일(`~/ros2_ws/install/setup.bash`, `~/.config/cyclonedds/r6.xml`, `.../vda_runtime.r006_map.yaml`, `~/ROS_DB/map/map.yaml`)을 검사하고 기존 bringup/VDA 실행을 중복 검사한다. 이어 Jazzy/workspace setup을 읽고 `ROS_HOSTNAME=R_006`, `ROS_DOMAIN_ID=6`, `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`, `CYCLONEDDS_URI=file://~/.config/cyclonedds/r6.xml`, `ROS_DB_PATH=/home/syscon/ROS_DB`를 설정한다. 마지막에 다음 구성을 시작한다.

```text
ros2 launch spx_bringup bringup.launch.py
  runtime_profile:=real use_sim_time:=false mode:=autonomous
  robot_model:=sl400_vri ns:=R_006 tf_prefix:=R_006
  localization:=true localization_tf_stub_enabled:=false
  map_yaml_file:=/home/syscon/ROS_DB/map/map.yaml
  core_task_config_file:=.../vda_runtime.r006_map.yaml
  task_sender_ingress_enabled:=false
  core_task_odom_hybrid_hil_enabled:=false
  core_task_map_id:=normal core_task_route_frame_id:=map
  imu_enabled:=true use_cp:=true
```

`bringup_normal()`은 `task_sender_ingress_enabled:=true`이고 R_006 VDA 프로필을 명시하지 않는다. 이번에 실행되어 있던 PID 1188의 인자는 `bringup()`과 일치했다. 두 명령을 같은 운용 프로필로 간주하면 안 된다.

**충전 명령:** `charge_up`이라는 셸 함수·실행 파일은 r56에 없다. `~/spx_scripts/charge_on`, `charge_off`, `charge_raw_on`, `charge_raw_off`는 존재한다. `charge_on/off:17`은 구 `/R_006/io/set/charge_relay`를 호출하지만 현재 ROS2 IO 구현 `spx_io_manager/src/io_driver_node.cpp:916-919`이 등록하는 것은 `/R_006/io/set/auto_charge_relay` (`std_srvs/srv/SetBool`)이다. 현재 코드 기준으로 `charge_on/off`를 정상 충전 절차로 안내할 수 없다. `charge_raw_on/off`는 ROS 경로를 거치지 않고 충전기 TCP(`192.168.3.150:2002` 기본값)에 비트를 직접 쓰므로 일반 운용 경로가 아니다.

충전 도킹의 설계 경로는 `RouteNavigation` 도킹 컨텍스트 `is_charge=true` → 위치 도킹 성공 → `spx_charging`이 `io/set/auto_charge_relay`를 켬 → `battery_state`의 충전 전류를 확인 → 성공/실패와 릴레이 정리다 (`spx_route_navigation_plugin/src/route_navigation_plugin.cpp:4580-4610`, `spx_charging/src/ros_charge_function.cpp:42-95,132-191`). 릴레이 서비스만 직접 호출하는 것은 위치 도킹과 BMS 전류 검증을 수행하지 않는다. 현 `bringup()`은 모든 확인된 작업 유입 경로를 비활성화하므로 EasyLoop에서 충전 도킹 Task를 바로 보낼 수 없다.

**현장에서 조회할 때**(읽기 전용):

```bash
type -a bringup charge_up charge_on charge_off
ros2 service list -t | grep -E 'auto_charge_relay|spx/set_mode'
ros2 topic echo --once /R_006/io/state_monitor/charging
ros2 topic echo --once /R_006/battery_state
```

물리 도킹과 현장 안전 조건을 확인한 뒤 릴레이를 수동으로 켜야 하는 경우의 실제 ROS2 서비스 형식은 `ros2 service call /R_006/io/set/auto_charge_relay std_srvs/srv/SetBool '{data: true}'`이며 끄는 요청은 `{data: false}`다. 이 호출은 실제 하드웨어 출력을 바꾸므로 이번 조사에서는 실행하지 않았다. 충전 성립은 서비스 응답만이 아니라 `battery_state` 전류와 충전 상태로 확인해야 한다. 현재 `bringup` 프로세스가 꺼져 있으므로 서비스 자체도 지금은 제공되지 않는다.

## Task·충전·맵 계약

`core_task.launch.py:27-98`은 `vda5050` 엔진을 선택한다. 프로세스 인자 기준 VDA 파라미터 적용 순서는 canonical `vda_runtime.yaml` → R_006 `vda_runtime.r006_map.yaml` → launch override다 (`vda_runtime.launch.py:606-618`). 현재 확인한 유효 파라미터는 `backend_mode=production`, `route_contract.frame_id=map`, `route_navigation.current_map_id=normal`이다.

R_006 프로필은 `RouteNavigation`, `StandBy`만 승인하며 `mqtt.enabled=false`, `ingress.ros_vda_enabled=false`, `ingress.ros_tma_enabled=false`, `ingress.ros_instant_actions_enabled=false`다 (`vda_runtime.r006_map.yaml:13-38,77-82`). 원본의 `ingress.ros_task_goal_enabled=true`는 `bringup()`의 `task_sender_ingress_enabled:=false`가 덮는다. 실제 조회에서도 `ingress.ros_task_goal_enabled=false`였다. EasyLoop는 이 상태에서 Task 입력을 지원하는 서비스가 없다고 표시해야 한다. 사용자 개입 없이 다른 작업 경로로 대체해서는 안 된다.

`ros_parameters_group/param/sl400_vri/system/vda_runtime.yaml:10-22`에 충전 전류 1.0 A, settle/timeout 등의 모델 설정이 있지만, 현재 VDA 프로세스 인자에는 **이 파일이 없다**. 따라서 이를 유효 충전 파라미터라고 단정하면 안 된다. 실행 중 파라미터를 별도로 조회해야 한다.

지도 `/R_006/map`은 Nav2 `OccupancyGrid`다. `map_server/load_map` (`nav2_msgs/srv/LoadMap`)이 실제 그래프에 있을 때만 EasyLoop가 지도 변경을 허용한다. `save_map`이나 ROS1 `change_map`을 r56에 있다고 가정하지 않는다.

## EasyLoop 구현 계약

| 모드 | 연결 방법 | 선택 기준 |
|---|---|---|
| 자동 | SSH에서 `ROS_VERSION`, `ROS_DISTRO`, `ros2`/`rostopic` 존재 확인 | ROS2면 SSH 경유 임시 ROS2 bridge, ROS1이면 기존 rosbridge |
| ROS1 수동 | 기존 `/ws-proxy` → 로봇 rosbridge | 그래프 type이 ROS2면 제어 차단 |
| ROS2 수동 | `/api/ros-runtime/prepare` → `/ws-ros2` | ROS2 설치 확인, 그래프 type 불일치면 제어 차단 |

r56에는 `rosbridge_server` 패키지와 프로세스가 없으며 EasyLoop 서버 호스트에는 ROS2가 설치되어 있지 않다. ROS2 모드는 서버의 기존 `ssh2` 연결을 이용해 로봇에서 파일 저장·설치 없이 일시적인 `rclpy` 프로세스를 구동하고, 그 stdin/stdout을 EasyLoop의 WebSocket에 연결한다. 이 프로세스는 EasyLoop 사용자가 ROS2 연결을 선택했을 때만 시작한다. 기존 ROS1 모드와 Test Mode 경로는 유지한다. 브리지는 `/rosapi` 조회, 토픽 구독·발행, 서비스 호출을 지원하고 타입은 실제 ROS2 그래프에서 검증한다. 맵/pose/조그용 복수 WebSocket은 한 SSH 세션의 독립 채널이다. ROS2 브리지에서 `/cmd_vel`과 `/cmd_vel_selected` 직접 발행은 차단한다.

EasyLoop의 r56 매핑: `/R_006/battery_state` (`sensor_msgs/msg/BatteryState`)를 SOC/전압/전류로 변환, `/R_006/robot_state` (`spx_robot_msgs/msg/RobotState`), `/R_006/io/state_monitor/{mode,sto,brake}`, `/R_006/cmd_vel_teleop`, `/R_006/io/set/auto_charge_relay`, `/R_006/spx/set_mode`, `/R_006/map`. Task는 현재 미검증으로 차단한다. `map_server/load_map`은 실시간 그래프에 있으면 허용한다.

2026-10-09 v1.4.0 이관에서 노드별 파라미터 조회·편집을 추가했다. 식별자는 `/R_006/amcl::max_particles`처럼 노드와 파라미터를 구분하며, 실제 선언된 타입과 서비스 결과를 검사한다. ROS2 액션의 goal/feedback/result/cancel 브리지도 구현했다. 일반 목적지 지정은 실제 `NavigateToPose` 서버가 있을 때만 사용한다. R_006의 수집 그래프에는 해당 서버가 없으므로 기존 VDA/RouteNavigation 실행 책임을 우회하지 않는다.

연결 시 로컬 `spx_bringup`의 namespace와 DDS 환경을 읽고 선택한 RID와 대조한다. 로컬 bringup 미확인 상태는 ROS 제어를 차단한다. ROS2 조그는 실제 mux/safety gate/wheel driver endpoint 연결을 확인한다. map/tf_static QoS는 실제 publisher 정책을 따르며 mode 전환으로 publisher가 바뀌면 다시 구독한다. 이미지 배열·비유한 숫자·legacy header/timestamp는 JSON/ROS2 형식으로 변환한다. Native ROS2 node/topic/service 상세 조회, bag record/play/info 및 디렉터리 탐색을 추가했다.

**검증 범위:** 브랜치의 단위 테스트·lint·Python 문법 검사는 통과했다. r56은 재조회 때 `bringup`이 종료되어 있어 실제 ROS2 브리지의 지도/상태 스트림과 하드웨어 명령은 실기기에서 실행 검증하지 않았다. 로봇 파일·패키지·설정은 변경하지 않았다.

전체 이관 사용법·지원 범위·실기 검증 한계는 [ROS1/ROS2 마이그레이션 안내](ros2-migration.md)를 참조한다. 위 9/29 원격 상태는 과거 스냅샷이다.
